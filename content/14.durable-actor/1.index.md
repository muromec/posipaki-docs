# A durable actor

An actor whose state is the fold of a durable record log, and whose only words are whether it took a request.

```ts
/** S is the state, R a record, Q a request, and E the spec's own word for a refusal. */
interface RecordSpec<S, R, Q, E = string> {
  filter(state: S, request: Q): { pass: true } | { refuse: E }; // may it go on
  map(state: S, request: Q): R;                                 // the record it becomes
  reduce(state: S | null, record: R): S;                        // one record onto the fold
  diff(before: S | null, after: S): R[];                        // the records that take one to the other
  producedFrom?(request: Q, record: R): boolean;                // was that record made of this request
}
```

Four words a spec has to answer, and one it may: `producedFrom` is for a follower that shows a record before the
authority has written it, and nothing else asks for it.

A caller says `ADD_RECORD`, `ATTACH` or `DETACH`, and hears `RECORD_ACCEPTED` or `RECORD_REJECTED`. There is no
third word: a process that cannot go on — its log ended, a record would not fold — dies with the reason, and a
caller waiting on it hears that it ended.

## Live demo

One log in the middle, a follower either side: the left one defers, the right one guesses. The four wires carry
records out from the log and requests in, and each can be carrying, slow, or cut.

Pick a shape, then click a box to place it there. To clear a box, click it again. Two of one shape on a board
clear the whole board.

## The demo's spec, in code

What follows is the code behind the widget above: one board, then a follower, then the five words.

```ts
/** What stands in a box. */
type Shape = "triangle" | "diamond" | "circle" | "square";

/** A 2×2 board: what stands in each box.  This is the state. */
type Board = { cells: (Shape | null)[] };

/** Something that happened to a box, or to the board.  These are the records. */
type BoardRecord =
  | { type: "PLACE"; cell: number; shape: Shape }
  | { type: "LIFT"; cell: number }
  | { type: "CLEAR" };

/** What a caller asks for: put a shape in a box, or take one out. */
type BoardAsk = { cell: number; shape: Shape | null };
```

A colour is how a shape is drawn and belongs to the page, not to the record: the same board renders the same
either way. A moment and an author belong to whoever builds the request, so the demo has no use for them.

## One actor

A log is anything with `send` and `onFrame`: a file, a socket, an array. `logChannel` is the last of those.

```ts
const log = logChannel([{ type: "CLEAR" }]);
const BoardActor = makeDurableActor(shapesSpec);

const board = await BoardActor.spawn({ log });
```

The actor reads the log when it starts, so its state is the fold of that one record before anything is asked of
it.

## Two actors

A follower is the same spec over a channel that hands it the fold where it arrives and every record after it. What
it sends requests through is one of two things: a call that answers, or a channel that only carries.

```ts
const FollowerActor = makeDurableProxyActor(shapesSpec);

const follower = await FollowerActor.spawn({
  upstream: board,                          // where a request goes
  log: mirrorChannel(board, shapesSpec),    // where it stands, then every change
});
```

A process is the shortcut: handed here it becomes a call in `optimistic` mode and a channel in `deferred`, because
a guess is taken back by an answer and a follower that makes no guesses has none to take back. `requesting(board)`
asks the same process as a call in either mode.

The follower holds no log of its own. Its requests travel to the process that owns one, and the answers come back
the same way — through a call always, and through a channel never, which is why a refusal is silence over one.

## Asking for a change

```ts
board.send({
  type: "ADD_RECORD",
  requestId: "r-1",
  request: { cell: 0, shape: "triangle" },
});

// → RECORD_ACCEPTED { requestId: "r-1" }
```

`requestId` is the caller's own handle on the request: it comes back with the answer, whichever answer that is.
`RECORD_ACCEPTED` is sent after the record has come back and been folded, so the state it was accepted for is
already the process's.

## `filter` — may it go on

```ts
filter(state, request) {
  const { cell, shape } = request;
  if (cell < 0 || cell >= state.cells.length) return { refuse: `${cell} is not a box` };
  const taken = state.cells[cell] !== null;
  if (shape === null && !taken) return { refuse: `box ${cell} is empty` };
  if (shape !== null && taken) return { refuse: `box ${cell} is taken` };
  return { pass: true };
}
```

`pass` lets `map` run. `refuse` writes nothing, and its sentence reaches the caller as `RECORD_REJECTED`.

## `map` — the record it becomes

```ts
map(_state, request) {
  const { cell, shape } = request;
  return shape === null ? { type: "LIFT", cell } : { type: "PLACE", cell, shape };
}
```

It is given the state and may ignore it: everything the record needs is in the request, because a value the spec
had to invent could not be rebuilt by a replay. It must be pure — the same state and request give the same
record, twice.

## `reduce` — one record onto the fold

```ts
reduce(state, record) {
  const cleared = () => ({ cells: [null, null, null, null] });
  if (record.type === "CLEAR") return cleared();

  const cells = state === null ? cleared().cells : [...state.cells];
  if (record.type === "LIFT") {
    cells[record.cell] = null;
    return { cells };
  }

  cells[record.cell] = record.shape;
  // Two of a shape do not stand: the second one clears the board.
  const twin = cells.some((shape, at) => shape === record.shape && at !== record.cell);
  return twin ? cleared() : { cells };
}
```

`null` is the state before the first record: the first `PLACE` lands on nothing and makes the board. A record this
spec cannot fold is a journal it cannot read, and the process dies with that sentence rather than guessing past it.

## `diff` — the way back

```ts
diff(before, after) {
  // From nothing: every shape that stands — or a CLEAR, because a follower has to be told something.
  if (before === null) {
    const places = after.cells.flatMap((shape, cell) =>
      shape === null ? [] : [{ type: "PLACE", cell, shape }]);
    return places.length === 0 ? [{ type: "CLEAR" }] : places;
  }

  // Nothing stands any more: one record says so for the whole board.
  if (after.cells.every((shape) => shape === null)) return [{ type: "CLEAR" }];

  // Otherwise one record per box that changed.
  return after.cells.flatMap((shape, cell) =>
    shape === (before.cells[cell] ?? null) ? [] :
    [shape === null ? { type: "LIFT", cell } : { type: "PLACE", cell, shape }]);
}
```

One step of `reduce` is one record, so an adjacent pair answers a list of one. With `null` for `before` it answers
every record needed to build the state, which is what a source starts a reader with — a list, so the vocabulary
needs no special "the whole board" record.

It is `reduce` inverted, which is why the state has to keep what its records said: a field the fold drops cannot
come back in a difference.

## Guessing

An `optimistic` follower shows the record it would ask for before the authority has written anything. So it queues
its requests locally, and has to work out which record coming back from the log answers which request.

By default, strictly: a record answers a request when it is the record `map` builds for it, compared whole. A spec
whose authority rewrites what it is given — a stamp, a server id — overrides that with `producedFrom`.

A request nothing answers stays queued. A refusal drops it, and the guesses made on top of it are replayed over the
fold without it.

## The laws

A spec is four functions, and four functions that exist can still be wrong. `conformance` checks the five things a
spec has to mean, against a case you write once:

```ts
const boardCase: LawCase<Board, BoardRecord, BoardAsk> = {
  name: "a board",
  spec: shapesSpec,
  journal: [{ type: "CLEAR" }, { type: "PLACE", cell: 0, shape: "triangle" }],
  allowed: { cell: 1, shape: "circle" },
  refused: { cell: 0, shape: "circle" }, // that box is already taken
};

// Five tests in your runner: "a board: fold", "a board: diff", …
conformance(boardCase, (name, run) => it(name, run));
```

The case is a journal, one request the spec must allow and one it must refuse — enough to catch what a spec usually
gets wrong. The journal has to fold to a state, since every law but `fold` is checked against it.

- **fold** — the same journal folds to the same state twice. The state is a function of the records and nothing else.
- **diff** — an adjacent pair of states diffs to exactly the record between them, and `diff(null, state)` reduced
  from nothing is the state again. This is what makes a follower arriving late correct rather than lucky.
- **map** — the allowed request passes the filter and maps to the same record twice. Purity, checked.
- **refusal** — the refused request is refused, and a refusal changes nothing: not the journal, not the state.
- **effect** — the allowed request moves the state, and `diff` names the record that moved it.

`conformance` takes the registrar instead of importing a test framework, so the same suite runs under vitest,
`node:test`, or a loop in a script. `runLaw` and `runLaws` answer the failures instead of throwing, for a runner
that wants to print them; `LAWS` is the five names.

The implementation is [`posipaki/packages/durable-actor`](https://github.com/muromec/posipaki/tree/main/packages/durable-actor).
