# A durable actor

An actor whose state is the fold of a durable record log, and whose only words are whether it took a request.

```ts
type FilterResult<E = string> = { pass: true } | { refuse: E };

interface RecordSpec<S, R, Q, E = string> {
  filter(state: S, request: Q): FilterResult<E>; // may it go on
  map(state: S, request: Q): R;                  // the record it becomes
  reduce(state: S | null, record: R): S;         // one record onto the fold
  diff(before: S | null, after: S): R;           // the way back
}
```

A caller says `ADD_RECORD`, `ATTACH` or `DETACH`, and hears `RECORD_ACCEPTED` or `RECORD_REJECTED`. There is no
third word: a process that cannot go on — its source went, a record would not fold — dies with the reason, and a
caller waiting on it hears that it ended.

## Live demo

One log in the middle, a follower either side: the left one defers, the right one guesses. The four wires carry
records out from the log and requests in, and each can be carrying, slow, or cut.

Pick a figure, then click a box to place it there. To clear a box, click it again. Two of one figure on a board
clear the whole board.

::demo{durable}

## The demo's spec, in code

What follows is the code behind the widget above: one board, then a follower, then the four words. The board is
four boxes, and a record says a figure went into one, came out of one, or that the board was cleared.

```ts
type Shape = "triangle" | "diamond" | "circle" | "square";
type Colour = "red" | "blue" | "yellow" | "green";
type Figure = { shape: Shape; colour: Colour };
type Board = { cells: (Figure | null)[]; by: string; at: number };

type BoardRecord =
  | { type: "PLACE"; at: number; by: string; cell: number; figure: Figure }
  | { type: "LIFT"; at: number; by: string; cell: number }
  | { type: "CLEAR"; at: number; by: string };

```

## One actor

A log is anything with `send` and `onFrame`: a file, a socket, an array. `logChannel` is the last of those.

```ts
const log = logChannel([{ type: "CLEAR", at: 0, by: "system" }]);
const Board = makeDurableActor(shapesSpec);

const board = await Board.spawn({ source: log });
```

The actor reads the log when it starts, so its state is the fold of that one record before anything is asked of
it.

## Two actors

A follower is the same spec over a channel that hands it the fold where it arrives and every record after it. What
it sends requests through is one of two things: a call that answers, or a channel that only carries.

```ts
const Follower = makeDurableProxyActor(shapesSpec);

const follower = await Follower.spawn({
  upstream: board,                             // where a request goes
  source: mirrorChannel(board, shapesSpec),    // where it stands, then every change
});
```

A process is the shortcut: handed here it becomes a call in `optimistic` mode and a channel in `deferred`, because
a guess is taken back by an answer and a follower that makes no guesses has none to take back. `requesting(board)`
asks the same process as a call in either mode.

The follower holds no log. Its requests travel to the process that owns one, and the answers come back the same
way — through a call always, and through a channel never, which is why a refusal is silence over one.

## Asking for a change

```ts
board.send({
  type: "ADD_RECORD",
  requestId: "r-1",
  request: { by: "board L", at: Date.now(), cell: 0, figure: { shape: "triangle", colour: "red" } },
});
// RECORD_ACCEPTED { requestId: "r-1" }
```

`RECORD_ACCEPTED` is sent after the record has come back and been folded: the state it was accepted for is
already the process's.

## `filter` — may it go on

```ts
filter(board, ask) {
  if (ask.cell < 0 || ask.cell >= 4) return { refuse: `${ask.cell} is not a box` };
  if (board.cells[ask.cell] !== null) return { refuse: `box ${ask.cell} is taken` };
  return { pass: true };
}
```

- It gets the state and the request.
- It answers `pass` or `refuse`.
- A refusal writes nothing.
- The sentence reaches the caller as `RECORD_REJECTED`.

## `map` — the record it becomes

```ts
map(board, ask) {
  if (ask.figure === null) return { type: "LIFT", at: ask.at, by: ask.by, cell: ask.cell };
  return { type: "PLACE", at: ask.at, by: ask.by, cell: ask.cell, figure: ask.figure };
}
```

- It gets the state and the request, and returns the record.
- It must be pure: the same state and request return the same record, twice.
- The moment and the author are in the request because only the caller knows them.

## `reduce` — one record onto the fold

```ts
reduce(board, record) {
  const cells = [...(board?.cells ?? [null, null, null, null])];
  if (record.type === "LIFT") cells[record.cell] = null;
  if (record.type === "PLACE") cells[record.cell] = record.figure;
  const twin = cells.some((cell, at) => cell !== null && at !== record.cell &&
    cell.shape === record.figure?.shape && cell.colour === record.figure?.colour);
  return { cells: twin ? [null, null, null, null] : cells, by: record.by, at: record.at };
}
```

- It gets the state so far and one record, and returns the state after it.
- `null` is the state before the first record: the first `PLACE` lands on nothing and makes the board.
- It throws for a record the journal cannot hold; the process dies with that sentence rather than guessing past it.

## `diff` — the way back

```ts
diff(before, after) {
  // From nothing: one record per figure that stands, and a CLEAR when none does — a follower has to hear
  // something to know the source has spoken.
  if (before === null) {
    const places = after.cells.flatMap((figure, cell) => figure === null ? [] :
      [{ type: "PLACE", at: after.at, by: after.by, cell, figure }]);
    return places.length === 0 ? [{ type: "CLEAR", at: after.at, by: after.by }] : places;
  }

  if (after.cells.every((cell) => cell === null)) return [{ type: "CLEAR", at: after.at, by: after.by }];
  for (let cell = 0; cell < 4; cell += 1) {
    const was = JSON.stringify(before.cells[cell] ?? null);
    const now = JSON.stringify(after.cells[cell] ?? null);
    if (was === now) continue;
    return [after.cells[cell] === null
      ? { type: "LIFT", at: after.at, by: after.by, cell }
      : { type: "PLACE", at: after.at, by: after.by, cell, figure: after.cells[cell] }];
  }
  return [{ type: "CLEAR", at: after.at, by: after.by }];
}
```

- It gets two states and returns the records that take one to the other.
- One step of `reduce` is one record, so an adjacent pair answers a list of one.
- With `null` for `before` it answers every record needed to build the state, which is what a source starts a
  reader with — a list, so the vocabulary needs no special "the whole board" record.
- It is `reduce` inverted, which is why the state has to keep what its records said: a field the fold drops cannot
  come back in a difference.

## Guessing

An `optimistic` follower shows a record the authority has not written yet. It keeps every request in flight in one
queue beside the records that arrive, and:

- a record that matches the oldest request settles it, so the guess becomes the authority's own record;
- a record that matches nothing is held behind the requests still in flight;
- a refusal drops that guess, and the guesses made on top of it are replayed over the fold without it — which is
  the difference from taking the fold back to where it was before the guess, and losing what came after.

Whether a record is the one a request produced is `producedFrom`, which defaults to the record `map` builds for it,
compared whole. A spec whose records the authority rewrites — with a stamp, a server id — has to say how to
recognise its own, or its guesses are never settled and the records behind them never reach the fold.

## The laws

`conformance` runs five laws against a spec — the case supplies a journal, one request the spec allows and one it
refuses:

```ts
import { conformance } from "posipaki-durable-actor";

conformance(counterCase, (name, run) => it(name, run));
```

An adjacent pair diffs to a list of one, and `diff(null, state)` reduced from nothing is the state again — that
second one is what makes a follower arriving late correct rather than lucky.

`runLaw` and `runLaws` answer the failures instead of throwing, for a runner of your own.

The implementation is [`posipaki/packages/durable-actor`](https://github.com/muromec/posipaki/tree/main/packages/durable-actor).
