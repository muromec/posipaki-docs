# Building your own transport

Remote actors are transport-agnostic: the seam (`serveRemoteActor` and
`remoteClient`) speaks only in a `Channel` of decoded frame objects, plus the
frame guards. Protocol, transport, and spawner are all pluggable, so the same
actor can run over Kafka, a Unix socket, WebRTC, or an in-memory pipe once you
write one transport and a spawner.

## The three layers

| Layer | Interface | You write it when |
| --- | --- | --- |
| Protocol | `json1Channel`, `encode` / `decode`, `VERSION` | reuse JSON (rarely write your own) |
| Transport | `StringTransport` or `Channel` | every new medium |
| Spawner | `Spawner` / `ClientSpawner` | every new medium |

The shipped FIFO, WebSocket, and worker transports are three concrete instances
of this pattern, and a useful reference for writing your own.

## Channel vs StringTransport

Frames are plain objects carrying one `$`-key each (`$proto`, `$init`, `$state`,
`$msg`, `$exit`). Two interfaces move them:

```ts
// decoded frame objects — the seam's currency
interface Channel {
  send(frame: Record<string, unknown>): void | Promise<void>;
  onMessage(handler: (frame: Record<string, unknown>) => void): void;
  removeHandler(): void;
  onClose(handler: () => void): void;
  close(): Promise<void>;
}

// encoded frame strings — for byte streams (Kafka, TCP, sockets, fifos)
interface StringTransport {
  send(frame: string): void | Promise<void>;
  onMessage(handler: (frame: string) => void): void;
  removeHandler(): void;
  onClose(handler: () => void): void;
  close(): Promise<void>;
}
```

`json1Channel(transport)` lifts a `StringTransport` into a `Channel` with JSON
encoding (`json.v1`). A medium with native message boundaries and structured
clone (such as `postMessage`) can implement `Channel` directly and skip JSON —
that's what `WorkerTransport` does (`clone.v1`).

## A transport

For a byte stream, implement `StringTransport`: frame each outgoing message and
split the incoming stream back into frames. Kafka or a Unix socket differs only
in how the bytes move:

```ts
import type { StringTransport } from "posipaki/remote";

type ByteStream = {
  write(data: string): void;
  on(event: string, cb: (chunk?: string) => void): void;
  end(): void;
};

class NewlineStreamTransport implements StringTransport {
  private handler: ((line: string) => void) | null = null;
  private closeHandler: (() => void) | null = null;
  private buffer = "";

  constructor(private stream: ByteStream) {
    stream.on("data", (chunk = "") => {
      this.buffer += chunk;
      let i: number;
      while ((i = this.buffer.indexOf("\n")) !== -1) {
        const line = this.buffer.slice(0, i);
        this.buffer = this.buffer.slice(i + 1);
        this.handler?.(line);
      }
    });
    stream.on("close", () => this.closeHandler?.());
  }

  send(frame: string) {
    this.stream.write(frame.endsWith("\n") ? frame : frame + "\n");
  }
  onMessage(handler: (line: string) => void) {
    this.handler = handler;
  }
  removeHandler() {
    this.handler = null;
  }
  onClose(handler: () => void) {
    this.closeHandler = handler;
  }
  async close() {
    this.stream.end();
  }
}
```

The shipped `FifoUtf8NlineTransport` is the full, defensive version — error
handling, idempotent close, and single-handler enforcement.

## A spawner

A spawner obtains the transport and performs the `$proto` handshake, keeping the
version string out of the seam. The server spawner **sends** it; the client
spawner **awaits and validates** it:

```ts
import { json1Channel, VERSION, isProto } from "posipaki/remote";

// server: () => Promise<Channel>
const serverSpawner = async () => {
  const channel = json1Channel(new NewlineStreamTransport(acceptConnection()));
  await channel.send({ $proto: VERSION });
  return channel;
};

// client: (args) => Promise<Channel>
const clientSpawner = async (args) => {
  const channel = json1Channel(new NewlineStreamTransport(openConnection(args)));
  const frame = await new Promise((resolve) => channel.onMessage(resolve));
  channel.removeHandler();
  if (!isProto(frame) || frame.$proto !== VERSION) {
    throw new Error("unsupported protocol");
  }
  return channel;
};
```

## Wire it into the seam

```ts
import { serveRemoteActor, remoteClient } from "posipaki/remote";

// server process
serveRemoteActor(actor, serverSpawner);

// client process
const proxy = remoteClient("myactor", clientSpawner);
const proc = await proxy.spawn(args);
proc.send({ type: "PING", count: 1 });
```

`remoteClient` returns a normal `ActorDefinition`, so `spawn`, `state`, and
`wait` behave like any other actor. `serveRemoteActor` takes the
`ActorDefinition` (not a bare function), so plugins and reflection survive the
trip.

## Structured-clone transports

If your medium moves objects rather than bytes, implement `Channel` directly and
handshake with `WORKER_VERSION` (`clone.v1`) instead of `VERSION` (`json.v1`).

## Handshake reference

| frame | direction | purpose |
| --- | --- | --- |
| `$proto` | server → client | version, once |
| `$init` | client → server | domain args + parent identity |
| `$state` | server → client | state snapshot |
| `$msg` | both | a message crossing the boundary |
| `$exit` | server → client | `{ code, state }` |
