# Ports

A port is values of one type between two ends, with three endings. Every medium produces one: a pair of named
pipes, a child's stdio, a socket, an HTTP request, a WebSocket. Every protocol is an adapter over one.

```ts
import { memoryChannelPair } from "posipaki/port";
import { spawnPort } from "posipaki/port/node";
```

## The channel

```ts
export interface Channel<F, C = string> {
  send(frame: F): Promise<void>;
  onFrame(handler: (frame: F) => void): () => void;
  onClose(handler: (reason: C) => void): () => void;
  onError(handler: (error: unknown) => void): () => void;
  close(reason?: string): Promise<void>;
  readonly info: Record<string, unknown>;
  control(command: Record<string, unknown>): void;
}
```

- `C` is what the far end says when it closes: a sentence for a socket, `{kind: "exit", code}` for a process.
- `info` is what the medium knows about itself. A process answers `{pid}`; an HTTP request answers
  `{method, url}`.
- `control` is how the medium is asked to act on what is behind it. A process takes `{signal: "SIGTERM"}`; an
  HTTP answer takes `{head: {status, headers}}`.

A channel ends three ways, and each has its own callback:

| ending | what it means |
| --- | --- |
| `close()` | this side ends it; idempotent |
| `onClose(reason)` | the far end ended it, with what it said |
| `onError(error)` | the wire failed; once, always followed by a close |

`send()` rejects once the channel is over, from either side.

## Media

```ts
import { memoryChannelPair, streamChannel } from "posipaki/port";
import { spawnPort, spawnPorts } from "posipaki/port/node";
```

| medium | function | frames |
| --- | --- | --- |
| a pair in memory | `memoryChannelPair<F>()` | `F`, both directions |
| a stream pair | `streamChannel({ read, write })` | `Uint8Array` |
| a child process | `spawnPort(command, options)` | `Uint8Array`, ending `ProcessEnd` |
| the same, with stderr | `spawnPorts(command, options)` | `{stdout, stderr}`, one exit for both |
| an HTTP request | `httpListener(options)` | a pair per request |

A spawned command is put in its own process group, and `close()` ends that group after `killAfterMs` (five
seconds by default), so what the command started ends with it. `control({signal})` asks first.

## Adapters

An adapter takes a channel and returns another over it.

| adapter | from | to |
| --- | --- | --- |
| `splitChannel(inner)` | `Uint8Array` | `Part` — a line and the octets it announced |
| `held(inner)` | any | the same, keeping frames that arrive before the first reader |
| `duplexChannel({inbound, outbound})` | a pair | one channel |
| `all(sources)` / `settled(sources)` | many | one, tagged by source |
| `json1(parts)` | `Part` | `Delivered` — a frame and its octets (`posipaki/remote`) |
| `handshake(inner)` | frames | the same, after both ends have named their protocol (`posipaki/remote`) |

A composition reads from the medium up: `handshake(json1(splitChannel(port)))`.

## The owner

A channel is not a process. `portActor` is one actor over one channel: it opens the channel in `setup`, so an
actor that is ready has a channel, and it closes the channel when it ends.

```ts
import { portActor } from "posipaki/port";
import { spawnPort } from "posipaki/port/node";

const Shell = portActor<{ command: string[] }, Uint8Array, unknown>({
  name: "shell",
  open: (args) => spawnPort(args.command),
});

const proc = await Shell.spawn({ command: ["/bin/sh", "-c", "echo hello"] });
proc.send({ type: "SEND", data: new TextEncoder().encode("to stdin\n") });
```

- in: `SEND { data }` writes to the channel; `SIGNAL { signal }` sends `{signal}` to `control`; posipaki's
  `STOP` ends the actor, which closes the channel.
- out: `DATA { data }` for every frame.
- state: `{ alive, end, info }`. The ending is state, not a message: when the channel closes, the actor writes
  `end`, clears `alive` and stops.

## HTTP

A response body is a channel, and so is a request body.

```ts
import { fetchPort } from "posipaki/port";

const body = await fetchPort("https://example.test/events", {
  init: { headers: { accept: "text/event-stream" } },
  connectMs: 15_000,
});
body.onFrame((chunk) => console.log(chunk.length));
body.onClose((end) => console.log("status", end.status));
```

- `fetchPort(url, options)` resolves once the response head has arrived. `close()` aborts the request.
- A response that is not a stream — a non-2xx, a refused connection — rejects before a channel exists, with an
  `HttpRefusal` that carries `status`.
- The channel's `info` carries `{url, status}`.

The other direction is a server:

```ts
import { httpListener } from "posipaki/port/node";
import { portReactor } from "posipaki/port";

const listener = httpListener<{ route: string }>({
  port: 8080,
  identify: (request) => {
    if (new URL(request.url).pathname !== "/events") throw new HttpRefusal(404, "nothing here");
    return { route: "events" };
  },
});

portReactor(listener, async ({ outbound }) => {
  outbound.control({ head: { status: 200, headers: { "content-type": "text/event-stream" } } });
  await outbound.send(new TextEncoder().encode("data: first\n\n"));
  await outbound.close();
});
```

- `accept()` gives `{ inbound, outbound, meta }`: the request body is a channel to read, the answer is a channel
  to write.
- The head is one command on the outbound channel, said before the first byte. A handler that writes without
  saying anything answers 200.
- `identify` runs before a pair exists, so a refusal costs no body. Throwing an `HttpRefusal` answers with its
  status; any other error answers 401.
- `listener.server` is the `node:http` server, for what only its consumer does — a WebSocket upgrade, another
  route.

## What a port does not do

- No backpressure: a channel accepts frames as fast as the reader takes them. A consumer that cannot keep up
  buffers, and the bound is the consumer's.
- No reconnection: a closed channel is closed. Spawning another is the caller's decision.
- No buffering of what was already read: a close does not replay frames a handler did not take.
